# 디자인 브리프 — 모바일 청첩장

와이어프레임 설계 기준(`와아어프레임.md`)의 순서를 그대로 적용한다:
**화면 목적 → 필요한 정보 → 정보 우선순위 → 사용자 행동 → UI Pattern → Layout → State → 제작**

## 1. 화면 목적

하객이 링크를 열고 **10초 안에 "누가 · 언제 · 어디서"를 파악**하고, 스크롤을 내리며 자연스럽게 **축하 행동(길 찾기 · 축의금 · 참석 응답 · 방명록)**까지 이어지게 한다.
동시에 신랑·신부에게는 "우리 결혼식답다"고 느껴지는 감정적 만족을 준다. 납품용이므로 **사진·문구·색만 바꿔도 품질이 유지되는 구조**여야 한다.

## 2. 정보 위계

| 위계 | 정보 | 근거 |
|---|---|---|
| **Primary** | 신랑·신부 이름, 예식 일시, 예식장 이름 | 하객의 첫 판단(갈지, 언제 비울지)에 필수 |
| **Secondary** | 인사말, 혼주 이름, 오시는 길 상세(교통·주차), 계좌 | 판단 후 실행에 필요 |
| **Supporting** | 갤러리, 신랑·신부 소개, 방명록, 안내사항, 공유 | 없어도 핵심 행동 가능, 감정·분위기 담당 |

그룹핑: "예식 일시"는 캘린더·D-day와 한 섹션 / "오시는 길"은 지도·네비 버튼·교통·주차를 한 섹션 / 계좌는 신랑측·신부측으로 묶고 각 3인.

## 3. 섹션 IA (모든 후보 공통 · 순서 고정)

| # | 섹션 | 목적 | UI Pattern | 주요 State |
|---|---|---|---|---|
| 0 | 오프닝 | 첫 3초의 인상 | 풀스크린 페이드/리빌 1회 | 재생 중 → 완료(스크롤 허용) |
| 1 | 커버 | Primary 3종 즉시 노출 | 히어로 이미지 + 이름 + 날짜·장소 한 줄 | 기본 |
| 2 | 인사말 | 초대의 말 + 혼주 | 텍스트 블록 + 혼주 2행 | 기본 |
| 3 | 신랑·신부 | 두 사람 소개 + 연락 | 2열 프로필 + 연락(전화·문자) 버튼 | 기본 |
| 4 | 예식 일시 | 날짜를 감정으로 | 월 캘린더(당일 강조) + D-day 카운트다운 | 카운트다운 실시간 |
| 5 | 갤러리 | 분위기 | 무드별 다른 레이아웃(그리드/콜라주/스트립) + 확대 뷰어 | Default / 확대 / 로딩 |
| 6 | 오시는 길 | **Primary Action** | 정적 지도 + 네비 3종 버튼(카카오맵·네이버·티맵) + 교통·주차·셔틀 리스트 | 기본 |
| 7 | 마음 전하실 곳 | Secondary Action | 신랑측/신부측 아코디언 + 계좌별 복사 버튼 + 카카오페이 | 접힘 / 펼침 / 복사 완료 토스트 |
| 8 | 참석 의사 | Secondary Action | CTA → 바텀시트(측·인원·식사) | Default / 입력 중 / 완료(감사 메시지) |
| 9 | 방명록 | Tertiary | 메시지 리스트 + 남기기 폼 | 목록 / Empty / 작성 완료 |
| 10 | 안내·공유·푸터 | 마무리 | 안내 3줄 + 카톡 공유·링크 복사 | 복사 완료 토스트 |

## 4. Action Hierarchy

- **Primary**: 오시는 길 → 지도 앱 열기 (예식 당일 가장 많이 눌리는 버튼)
- **Secondary**: 계좌 복사, 참석 의사 전달
- **Tertiary**: 방명록 남기기, 공유, 전화·문자

한 화면에 Primary급 버튼은 하나만 강조한다. 계좌 복사는 행 단위의 작은 버튼, RSVP는 섹션 하단 CTA 하나.

## 5. 인터랙션 정의

- 계좌 복사: 탭 → 클립보드 복사 → 토스트 "계좌번호가 복사되었습니다" 1.8초 → 사라짐
- RSVP: CTA 탭 → 바텀시트 열림 → 측(신랑/신부)·참석 여부·인원·식사 선택 → 전달 → 시트 내용이 감사 메시지로 교체 → 닫기
- 갤러리: 사진 탭 → 풀스크린 뷰어(스와이프·닫기) → 닫기
- 네비 버튼: 탭 → 해당 앱 스킴/URL 새 창
- 스크롤 등장: 섹션 진입 시 1회 fade-up(IntersectionObserver), 과하지 않게 400~700ms

## 6. 공통 제작 스펙

- 단일 HTML(인라인 CSS·JS), 외부 의존은 Google Fonts·Pretendard CDN·Unsplash 이미지뿐
- 기준 폭 390px. 데스크탑에서 열면 배경 위에 폰 컬럼으로 중앙 정렬(업체 시연용)
- 콘텐츠는 `content/mock.json`을 그대로 인라인 (모든 후보 동일)
- 접근성: 본문 최소 14px, 대비 4.5:1 이상, 터치 타깃 44px 이상
- **금지**: 핑크·보라 그라데이션, 스크립트 폰트 남발, 카드 안 카드, 과한 드롭섀도, 반짝이 파티클, 뜻 없는 영문 헤더 남발, 지도 iframe 풀폭

## 7. 판단 기준 (라운드 리뷰 시 체크)

1. 커버에서 이름·날짜·장소가 3초 안에 읽히는가
2. 섹션 제목 처리가 템플릿 티 없이 무드에 녹아 있는가
3. 캘린더·D-day가 "정보"를 넘어 "감정"으로 느껴지는가
4. 계좌·네비·RSVP가 무드를 깨지 않으면서도 즉시 눌리는가
5. 여백 리듬이 처음부터 끝까지 일관한가
6. 물성 장치(종이·필름·그레인·괘선 등)가 최소 1개 있고 과하지 않은가
7. 위 클리셰 목록에 걸리는 요소가 0개인가

## 8. 명시적 가정

- 플랫폼: 모바일 웹(카카오톡 인앱 브라우저 최우선). 데스크탑은 시연용 프레임만 제공
- 지도는 정적 이미지·플레이스홀더로 대체(실서비스에서 카카오맵 SDK 교체). 네비 버튼은 실제 스킴 URL 사용
- 카카오톡 공유는 SDK 없이 링크 복사로 대체
- 사진은 Unsplash 웨딩 이미지 임시 사용, 납품 시 고객 사진으로 교체
- 예식일 2026-11-14 기준 D-day 계산
