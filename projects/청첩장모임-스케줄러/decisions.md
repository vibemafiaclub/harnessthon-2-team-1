# Decisions — 청첩장모임 스케줄러

## 이번 프로젝트에서 B단계가 좁혀진 이유

표준 하네스의 B단계 축(비주얼 무드·정보밀도 전반)은 design.md가 이미 확정한 디자인 시스템 안에서는 대부분 닫혀 있다. 색·타이포·컴포넌트 스타일을 다시 발산시키는 것은 부록C "결정하면 안 되는 것"(새 색상·새 폰트·새 radius 도입)을 위반한다. 따라서 이번 B단계는 **design.md 컴포넌트를 조합하는 방식**과 **정보 표시 레이아웃** 두 축으로만 좁혀 진행했다.

## 식별된 독립 축

- **축 1: 회신 현황 표시 방식** — 그리드 히트맵(가로: 날짜, 세로: 사람) vs 리스트(사람당 1행 + 상태칩 나열). 서로 다른 실패 모드를 가짐(그리드는 인원 많을 때 가로스크롤, 리스트는 날짜 많을 때 칩 줄바꿈) → 독립적으로 비교해야 confound가 안 생김.
- **축 2: 탭 구조 밀도** — 3탭(홈/모임/지인풀) vs 4탭(+더보기). PRD 조건("두 사람이 함께 쓰는 것")에 직접 영향을 주는 축.

## 축별 후보·비교·선택

### 축 1: 회신 현황 표시 방식

두 후보를 실제 클릭 가능한 로우파이 프로토타입으로 만들어 비교함 (Artifact, 그리드 셀 토글 시 하단 합계 실시간 갱신 vs 카카오톡 스타일 채팅 스크롤).

| 후보 | 설명 | 비교 근거 | 선택 여부 |
|---|---|---|---|
| A. 그리드 히트맵 | 사람×날짜 매트릭스, 셀 클릭으로 가능/불가능 토글 | 한눈에 겹치는 날짜 파악 유리. 단 design.md 모바일 프레임(390px)에서 참석자 5~6명(PRD §3 표준 모임 규모) 초과 시 가로스크롤 발생 → design.md의 "가로스크롤 지양, 세로 스크롤 우선" 원칙과 충돌 | ❌ |
| B. list-row + status-chip | 사람 1명당 1행, 우측에 가능한 날짜를 상태칩으로 나열 | design.md 기존 컴포넌트(list-row, status-chip) 그대로 재사용 가능(부록C 허용 범위: "기존 컴포넌트 조합"). 세로 스크롤이라 인원이 늘어도 레이아웃이 안정적 | ✅ |

**선택 이유**: PRD §3 "모임당 3~6명, 많으면 상견례 등 양가 합류로 늘어남"이라는 현실적 규모 조건에서, 그리드는 인원 증가에 취약하고 design.md가 이미 정한 프레임 폭(390px) 제약과 정면충돌한다. 리스트형은 새 컴포넌트 없이 기존 토큰만으로 구현 가능해 부록C 권한 경계 안에서 해결된다.

**UX 관점 교차비평**: 그리드는 "누가 몇 명 겹치는지"를 한 화면에서 파악하는 데는 여전히 리스트보다 빠르다. 리스트 선택 시 이 손실을 보완하려면 리스트 하단에 "가장 많이 겹치는 날짜" 요약 행을 유지해야 한다(방금 만든 로우파이의 tfoot 역할).
**개발호환성 관점 교차비평**: 그리드는 동적 인원수에 대해 반응형 테이블 처리가 필요해 컴포넌트 재사용성이 낮다(신규 컴포넌트 필요 → 부록C 위반 소지). 리스트는 list-row를 데이터 배열에 map하는 것만으로 확장되어 구현 비용이 낮다.

### 축 2: 탭 구조 밀도

| 후보 | 설명 | 비교 근거 | 선택 여부 |
|---|---|---|---|
| 3탭 (홈/모임/지인풀) | 확정·후보·상태구분을 모임 상세 안으로 흡수 | "두 사람이 함께" 조건에서 탭이 적을수록 배우자와 화면 상태를 맞추기 쉬움. design.md 모바일 탭바는 3~5개 권장 범위 | ✅ |
| 4탭 (+더보기: 배우자 계정 연동·알림설정) | 계정/설정 기능을 별도 탭으로 분리 | 설정류 기능이 PRD 핵심 유저스토리에 없어 사람 게이트에서 과잉 스코프로 판단 | ❌ |

**선택 이유**: 사람 게이트(AskUserQuestion)에서 3탭 직접 선택. PRD 핵심 유저스토리 3개(예비신부/지인/예비신랑) 모두 "묶기·응답·조망"에 관한 것이지 계정 설정에 관한 것이 아니므로, 4탭의 "더보기"가 다루려던 기능은 이번 스코프 밖으로 자연 제외.

## 남은 트레이드오프

- list-row 방식은 "동시에 여러 명이 가능한 날짜"를 파악하려면 하단 요약 행에 의존한다 — 모임 인원이 10명을 넘는 극단적 케이스(PRD상 발생 가능성 낮음, 대학 동기 모임 등)에서는 다시 가독성이 떨어질 수 있음. 발생 시 A단계보다 C단계(정보밀도 번잡함 여부)에서 걸러질 가능성이 높다.
- 3탭 구조는 "배우자 계정 전환" 같은 상세 조건(PRD 조건란)을 별도 화면 없이 홈 탭 상단 토글 등으로 흡수해야 한다 — 이 배치는 B단계에서 확정하지 않았으므로 화면 설계 단계에서 추가로 결정 필요.
