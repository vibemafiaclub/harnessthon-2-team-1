# 범용 리스크 패턴 12

이 파일은 **프로젝트마다 바뀌지 않는 상수**다. 도메인이 청첩장이든 커머스든 예약이든 병원이든, 기획에서 빠뜨리면 나중에 반드시 터지는 지점들을 모아둔 것이다.

하네스는 매 프로젝트에서 각 패턴에 대해 세 가지를 판정한다.

1. **해당 여부** — 이 도메인에 이 패턴이 존재하는가
2. **발현형** — 존재한다면 무엇으로 나타나는가 (`EC-` 로 정의)
3. **대응 위치** — 어느 화면(`SCR-`)·어느 정책(`POL-`)에서 다루는가

세 가지가 모두 채워져야 STEP 5를 통과한다. 해당 없음으로 판정할 수는 있지만, **판정 없이 비워둘 수는 없다.**

## RISK-01 다대다 귀속 모호성

**정의** 한 대상이 여러 분류에 동시에 속할 수 있어, 어디에 넣을지 판단이 필요한 상황.

| 도메인 | 발현 |
|---|---|
| 청첩장 스케줄러 | 한 지인이 대학 동기이자 직장 동료 |
| 커머스 | 상품이 여러 카테고리에 노출 |
| 교육 | 강사가 여러 과목 담당 |
| 병원 | 환자가 여러 진료과에 동시 등록 |

**확인 질문** 중복 소속을 허용하는가? 허용한다면 목록에서 중복 노출되는가, 대표 분류를 지정하는가? 한쪽에서 삭제하면 다른 쪽은?
**반영 위치** `ia.yaml`의 엔티티 관계(다대다 여부), 목록 화면의 중복 처리, `policy.md`

## RISK-02 응답 타임아웃 / 마감

**정의** 상대의 응답을 기다려야 하는데 무한정 기다릴 수 없어, 마감과 그 이후 처리가 필요한 상황.

| 도메인 | 발현 |
|---|---|
| 청첩장 스케줄러 | 날짜 후보를 보냈는데 며칠째 무응답 |
| 커머스 | 미입금 주문 |
| 예약 | 확정 대기 중 만료 |
| 채용 | 제안 수락 기한 |

**확인 질문** 마감을 누가 정하는가? 마감 후 미응답자는 어떻게 처리되는가(자동 제외/보류/재발송)? 마감 전 리마인드가 있는가?
**반영 위치** `flows.yaml`의 상태 전이(만료 경로), `policy.md`, 대기 목록 화면

## RISK-03 리소스 충돌

**정의** 유한한 자원(시간·재고·좌석·인력)이 동시에 두 곳에 배정될 수 있는 상황.

| 도메인 | 발현 |
|---|---|
| 청첩장 스케줄러 | 같은 날 저녁에 모임 두 건 |
| 커머스 | 마지막 재고에 동시 주문 |
| 예약 | 같은 슬롯 더블부킹 |
| 회의실 | 시간대 중복 |

**확인 질문** 충돌을 사전에 막는가, 경고만 하는가, 사후에 알리는가? 의도적 중복이 허용되는 경우가 있는가?
**반영 위치** 전체 조망 화면의 충돌 표시, 확정 시점의 경고, `policy.md`

## RISK-04 공동 소유·권한 분기

**정의** 하나의 데이터를 둘 이상이 함께 소유·관리하며, 각자 볼 수 있는 범위와 할 수 있는 행동이 다른 상황.

| 도메인 | 발현 |
|---|---|
| 청첩장 스케줄러 | 신랑·신부가 각자 지인 풀 관리, 일정은 공유 |
| 커머스 | 멀티 판매자, 본사와 지점 |
| 협업툴 | 소유자·편집자·뷰어 |
| 가족 서비스 | 보호자 공동 계정 |

**확인 질문** 상대가 만든 것을 수정·삭제할 수 있는가? 누가 했는지 표시되는가? 동시에 편집하면?
**반영 위치** `users.md`의 권한표, `policy.md`, 목록에서의 소유자 구분 표시

## RISK-05 정상 플로우 우회

**정의** 급하거나 예외적인 상황에서 정규 절차를 건너뛰어야 하는 경로.

| 도메인 | 발현 |
|---|---|
| 청첩장 스케줄러 | 2주 전 급하게 잡는 모임 (후보 제시·회신 수합 생략) |
| 커머스 | 관리자 강제 취소·환불 |
| 예약 | 당일 워크인 |
| 승인 워크플로 | 긴급 결재 |

**확인 질문** 우회 경로가 필요한가? 누가 쓸 수 있는가? 우회한 건은 정상 건과 구분해서 보이는가?
**반영 위치** `flows.yaml`의 축약 플로우, `policy.md`

## RISK-06 대량 데이터 탐색

**정의** 목록이 수십~수백 건으로 늘어났을 때 원하는 것을 찾지 못하게 되는 상황.

| 도메인 | 발현 |
|---|---|
| 청첩장 스케줄러 | 지인 100명 목록에서 특정인 찾기 |
| 커머스 | 상품 수천 개 |
| CRM | 고객 목록 |

**확인 질문** 예상 최대 건수는? 검색·필터·정렬·그룹핑 중 무엇이 필요한가? 기본 정렬 기준은?
**반영 위치** 목록 화면 정의에 검색·필터 항목 명시, `project-profile.yaml`의 데이터 규모

> 데이터 규모는 화면 설계를 바꾼다. 5건일 때와 100건일 때는 다른 화면이다. `seed-data.json`을 실제 규모로 생성해야 하는 이유.

## RISK-07 빈 상태

**정의** 아직 데이터가 하나도 없는 시점. 신규 사용자가 반드시 처음 만나는 화면이다.

| 도메인 | 발현 |
|---|---|
| 청첩장 스케줄러 | 지인 0명, 모임 0건인 최초 진입 |
| 커머스 | 장바구니·주문내역 없음 |
| 어디든 | 검색 결과 0건, 필터 결과 0건 |

**확인 질문** 각 목록 화면의 빈 상태에서 무엇을 안내하고 어디로 유도하는가? 최초 온보딩이 필요한가?
**반영 위치** 모든 목록·조망 화면의 상태 변형 목록에 빈 상태 필수 기재

## RISK-08 부분 완료

**정의** 완료도 미완료도 아닌 중간 상태. 진행률을 보여줘야 하는 지점.

| 도메인 | 발현 |
|---|---|
| 청첩장 스케줄러 | 6명 중 4명만 회신 |
| 커머스 | 일부 상품만 배송 |
| 설문 | 작성 중 이탈 |

**확인 질문** 부분 완료를 어떤 단위로 표시하는가(n/m, %, 상태 배지)? 부분 상태에서 다음 단계로 넘어갈 수 있는가?
**반영 위치** `flows.yaml`의 상태 정의, 목록 화면의 진행 표시

## RISK-09 취소·되돌리기

**정의** 확정된 것을 되돌리는 경로. 기획에서 가장 자주 누락되는 항목.

| 도메인 | 발현 |

| 예약 | 예약 변경 |

**확인 질문** 되돌릴 수 있는 단계는 어디까지인가? 되돌리면 관련자에게 알리는가? 되돌린 이력이 남는가?
**반영 위치** `flows.yaml`의 역방향 전이, `policy.md`

## RISK-10 외부·미인증 사용자 진입

**정의** 계정 없이 링크만으로 들어오는 사용자가 있는가.

| 도메인 | 발현 |
|---|---|
| 청첩장 스케줄러 | 초대받은 지인이 링크로 들어와 회신 |
| 커머스 | 비회원 주문·조회 |
| 설문 | 익명 응답 |

**확인 질문** 미인증 사용자는 무엇을 볼 수 있고 무엇을 못 보는가? 본인 확인은 어떻게 하는가? 링크가 유출되면?
**반영 위치** `users.md`에 별도 역할로 정의, 전용 화면 분리, `policy.md`

> 이 패턴이 해당되면 화면 수가 눈에 띄게 늘어난다. 로그인 사용자용 화면을 그대로 재사용할 수 없다.

**확인 질문** 어떤 사건에 누구에게 알리는가? 채널은(앱푸시·문자·카카오·메일)? 사용자가 끌 수 있는가?
**반영 위치** `policy.md`의 알림 정의표, `flows.yaml`의 상태 전이에 알림 트리거 표기
