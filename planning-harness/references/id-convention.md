# ID 체계

모든 산출물은 산문 대신 ID로 서로를 가리킨다.
"모임 상세 화면에서 처리한다"가 아니라 "`SCR-07`에서 처리한다"로 쓴다.
이 규칙이 지켜져야 `scripts/validate_ids.py`가 누락과 고아 참조를 잡아낼 수 있고, 다음 하네스가 문서를 파싱할 수 있다.

## 접두사

| 접두사 | 대상 | 정의 위치 | 예 |
|---|---|---|---|
| `REQ-` | 요구사항 | `definition.md` | `REQ-04` |
| `ROLE-` | 사용자 역할 | `users.md` | `ROLE-02` |
| `ENT-` | 데이터 엔티티 | `ia.yaml` | `ENT-03` |
| `SCR-` | 화면 | `ia.yaml` | `SCR-11` |
| `FLW-` | 유저 플로우 | `flows.yaml` | `FLW-02` |
| `ST-` | 상태 (상태 전이도의 노드) | `flows.yaml` | `ST-05` |
| `ONB-` | 온보딩 경로 (역할·진입별 첫 진입 → 첫 가치) | `onboarding.yaml` | `ONB-02` |
| `POL-` | 정책 | `policy.md` | `POL-08` |
| `RISK-` | 범용 리스크 패턴 | `references/risk-patterns.md` (고정) | `RISK-03` |
| `EC-` | 엣지케이스 (리스크의 이 프로젝트 발현형) | `validation.csv` | `EC-06` |

## 번호 규칙

- 두 자리 zero-pad: `SCR-01`, `SCR-02` … `SCR-10`. 100개를 넘으면 세 자리로 전환하되 프로젝트 내에서 자릿수를 섞지 않는다.
- 부여 순서는 **정의된 순서**를 따른다. 중요도 순이 아니다.
- **한 번 부여한 번호는 재사용하지 않는다.** 항목을 삭제해도 번호는 결번으로 남긴다. 재번호를 매기면 다른 문서의 참조가 전부 깨진다.
- 하위 구분이 필요하면 점을 쓴다: `SCR-07.1` (모달·시트 등 독립 화면으로 세지 않는 부속 화면).
- `ONB-` 경로 안의 단계는 별도 ID를 갖지 않는다. 순서로 식별하고, 다른 문서에서는 경로 ID(`ONB-02`)까지만 가리킨다.

## 참조 표기

- 문서 본문: 백틱으로 감싼다 — `` `SCR-07` ``
- YAML 필드: 문자열 그대로 — `screen: SCR-07`
- 복수 참조: 배열 — `screens: [SCR-07, SCR-08]`
- 참조만 하고 정의하지 않은 ID가 있으면 검증 실패다. 반대로 정의만 되고 아무도 참조하지 않는 ID(고아)도 경고 대상이다.

## `RISK-` 는 예외

`RISK-01` ~ `RISK-12`는 `references/risk-patterns.md`에 고정된 상수다. 프로젝트마다 새로 만들지 않고, 번호·이름을 바꾸지 않는다.
프로젝트에서 실제로 나타난 형태는 `EC-` 로 새로 정의하고 `RISK-` 를 참조한다.

```
EC-03: 한 지인이 대학·직장 두 그룹에 동시 소속 → RISK-01의 발현형, SCR-04에서 처리
```

## 금지

- 같은 대상에 두 개의 ID를 부여하는 것
- ID 없이 화면·플로우를 언급하는 것
- 접두사를 임의로 신설하는 것 (필요하면 사용자에게 먼저 물어본다)
