# 입력 보완 인터뷰

원본 자료가 부실해 지어내야 할 상황이면 **작업을 멈추고** 여기서 질문한다.
추측으로 채운 기획은 나중에 전부 뒤집힌다. 물어보는 비용이 훨씬 싸다.

## 질문 원칙

- **한 번에 3~5개까지.** 20개를 한꺼번에 던지면 답이 안 온다
- **선택지를 제시한다.** "알림은 어떻게 하시나요"보다 "카카오 알림톡 / 문자 / 앱푸시 / 미정 중 어느 쪽인가요"가 답하기 쉽다
- **모르면 모른다고 답할 수 있게 한다.** "미정"도 유효한 답이다. 미정으로 확인된 것은 `TBD:`로 남기면 되고, 이건 지어낸 것과 완전히 다르다
- **답을 못 받아도 진행한다.** 답이 없으면 `TBD:`로 남기고 다음 스텝으로 간다. 멈춰 있는 것이 더 나쁘다

## 스텝별 필수 확인 항목

### STEP 1 전에

1. 이 서비스를 실제로 쓰는 사람은 몇 종류인가? 각자 로그인하는가?
2. 이번 범위에서 **만들지 않는 것**은 무엇인가?
3. 기존 시스템·데이터가 있는가, 완전 신규인가?
4. 납품 기한과 이후 단계(디자인·개발) 일정은?

### STEP 2 전에

5. 각 목록의 예상 최대 건수는? (10건 / 100건 / 1,000건 이상)
6. 계정 없이 링크로 들어오는 사용자가 있는가?
7. 모바일 우선인가, 데스크탑 우선인가, 둘 다인가?

### STEP 3 전에

8. 완료·확정된 것을 되돌릴 수 있어야 하는가?
9. 사용자 행동 없이 시간이 지나면 자동으로 바뀌어야 하는 것이 있는가?

### STEP 4 전에

10. 알림 채널은 무엇인가? (카카오 알림톡 / 문자 / 이메일 / 앱푸시 / 미정)
11. 개인정보를 수집하는가? 보관 기간 규정이 있는가?
12. 지원해야 하는 브라우저·디바이스 범위가 정해져 있는가?

## 답변 기록

받은 답변은 해당 산출물에 반영하고, 원본 자료에 없던 내용임을 표시한다.

```
POL-07 미회신자는 마감 후 자동 제외한다 [인터뷰 확인, 2026-09-05]
```

출처를 표시해야 나중에 "이건 어디서 나온 규칙이냐"는 질문에 답할 수 있다.
