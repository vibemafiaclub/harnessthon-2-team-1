### 조건부 항목 상세

| ID | 조건 |
|---|---|
| POL-01 | 배우자가 만든 모임의 확정·취소는 원칙적으로 생성자만 할 수 있다. 다만 결혼식까지 2주 이내로 임박했는데 생성자가 회신 마감 내 확인을 못한 경우에 한해 배우자가 대신 확정·취소할 수 있다 (RISK-04 공동 소유와 RISK-05 우회 경로의 접점). 대신 처리한 건은 모임 상세(`SCR-06`)에 "배우자가 대신 처리함"으로 표시한다. |

## 2. 상태·예외 정책

| ID | 상황 | 처리 규칙 | 관련 |
|---|---|---|---|
| POL-02 | 회신 마감 후 미응답자 처리 | 마감이 지나도 시스템이 자동으로 제외하지 않는다. 상태만 `ST-01`→`ST-02`(확정대기)로 바뀌고, 실제 제외·재발송·마감 연장은 모임 생성자가 `SCR-06`에서 수동으로 선택한다. | RISK-02, `FLW-02` |
| POL-03 | 리소스 충돌(같은 날짜 중복) | 차단하지 않고 경고만 표시한다(`SCR-06`, `SCR-07`). 오전/오후로 나눠 의도적으로 겹치는 경우가 실제로 있기 때문이다. | RISK-03, `FLW-02`, `FLW-06` |
| POL-04 | 취소 가능 단계와 취소 후 처리 | 확정 전(`ST-01`,`ST-02`)에는 제한 없이 취소 가능. 확정 후(`ST-03`)에는 사유 입력을 권장하되 필수는 아니며, 취소 시 배우자와 참가 지인 전원에게 알린다(POL-19). 취소된 모임은 삭제하지 않고 `ST-05`로 보관한다(POL-11). | RISK-09, `FLW-07` |
| POL-05 | 우회 경로(긴급 모임) 사용 조건과 주체 | `ROLE-01`/`ROLE-02` 누구나 별도 승인 없이 사용 가능. 다만 긴급 모임임을 목록·상세 화면에 항상 표시해 정상 절차를 거친 모임과 구분한다. | RISK-05, `FLW-06` |
| POL-06 | 지인 등록 시 연락처 중복 | 이미 등록된 연락처로 다시 등록을 시도하면 저장을 막지 않되, 기존 레코드가 있음을 안내하고 "기존 레코드에 그룹만 추가"를 기본 선택지로 제시한다. | `FLW-01` |
| POL-07 | 그룹 미지정 지인 저장 | 그룹을 하나도 선택하지 않아도 저장을 허용한다. 목록에서는 "미분류" 필터로 노출한다. | `FLW-01` |
| POL-08 | 배우자 계정 연결 오류 | 잘못된 초대 코드는 재입력을 요청한다. 이미 다른 계정과 연결된 코드는 연결을 거부한다 — 커플은 정확히 2개 계정만 허용되기 때문이다(`ia.yaml` ENT-07). | `FLW-03` |
| POL-09 | 초대받은 지인의 마감 후 접근·마감 전 수정 | 마감이 지나면 회신 입력을 막고 확정된 날짜가 있으면 결과만 보여준다. 마감 전에는 기존 회신을 몇 번이든 다시 열어 수정할 수 있다. | RISK-02, `FLW-05` |

## 3. 데이터 정책

| ID | 항목 | 규칙 |
|---|---|---|
| POL-10 | 중복 소속 (RISK-01) | 지인의 다중 그룹 소속을 허용한다. 그룹을 삭제해도 지인 레코드는 삭제되지 않고 해당 그룹 태그만 제거된다. |
| POL-11 | 삭제 방식 | 지인·그룹·모임 모두 실제 삭제가 아닌 소프트 삭제(숨김 처리)로 한다. 확정 이력이 있는 모임은 삭제 자체를 막고 취소(`ST-05`) 처리만 허용한다. |
| POL-12 | 완료 항목 보관 (RISK-12) | 완료·취소된 모임은 별도 삭제 없이 "완료" 탭에 계속 남긴다. 구체적인 보관 기간은 `TBD:` — 클라이언트 확인 필요. |
| POL-13 | 최대 건수 (RISK-06) | 지인 등록 수에 상한을 두지 않되, 100명을 기준으로 검색·그룹 필터 UI가 항상 노출되도록 한다 (`project-profile.yaml` data_scale 참고). |
| POL-14 | 개인정보 보관·파기 | `TBD:` — 지인 연락처의 보관 기간·파기 절차는 법무 검토가 필요하다 (`project-profile.yaml` constraints.legal). |
| POL-15 | 초대받은 지인의 전역 식별 기준 (RISK-10) | 전화번호를 식별 키로 잠정 채택한다. 전화번호 변경·공유로 인한 오식별 위험이 있어 최종 확정 전 클라이언트 확인이 필요하다. `TBD:`. |
