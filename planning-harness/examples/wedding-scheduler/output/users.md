# 사용자 정의

## 역할 목록

| ID | 역할 | 인증 | 한 줄 설명 |
|---|---|---|---|
| ROLE-01 | 예비신부 | 로그인 | 자신의 지인 풀을 관리하고 모임을 편성·조율한다 |
| ROLE-02 | 예비신랑 | 로그인 | 자신의 지인 풀을 관리하고 모임을 편성·조율하며, 배우자와 일정을 공유한다 |
| ROLE-03 | 초대받은 지인 | 비인증 (초대 링크) | 여러 모임 요청을 모아보고 참석 가능 여부를 회신한다 |

ROLE-01과 ROLE-02는 권한 구조가 대칭이다(둘 다 로그인, 둘 다 자신의 지인 풀 관리, 둘 다 상대의 확정 일정을 열람). 이름을 분리한 이유는 데이터 소유 범위가 다르기 때문이다 — "역할 간 관계"의 RISK-04 참고.

## ROLE-01 예비신부

**목표**
자신의 지인(대학·직장·동네 등)을 모임 단위로 묶어 청첩장모임을 잡고, 배우자의 일정과 합쳐 결혼식 전까지 남은 모임을 놓치지 않는 것.

**진입 경로**
로그인 (계정 생성 후).

**권한**

| 구분 | 내용 |
|---|---|
| 볼 수 있는 것 | 자신이 등록한 지인·그룹·모임, 배우자(ROLE-02)가 확정한 모임을 포함한 통합 일정 조망, 양가 공동 모임 |
| 만들 수 있는 것 | 지인 등록, 그룹 편성, 모임 생성(1:1 포함), 날짜 후보 제안, 배우자와 함께 참여하는 공동 모임 생성 |
| 수정·삭제할 수 있는 것 | 자신이 등록한 지인·모임 정보, 자신이 만든 모임의 날짜 후보 수정, 회신 마감 기한 연장 |
| 할 수 없는 것 | 배우자(ROLE-02)가 등록한 지인 정보를 직접 수정·삭제 (RISK-04), 초대받은 지인(ROLE-03)의 회신을 대신 확정 처리 |

**주요 시나리오**
`FLW-01`(지인 등록), `FLW-02`(모임 편성·일정 조율), `FLW-04`(전체 일정 조망) 참조.

## ROLE-02 예비신랑

**목표**
자신의 지인 풀을 관리하며 모임을 잡고, 배우자와 각자 진행 중인 모임을 합쳐 결혼식까지 일정이 겹치지 않는지 확인하는 것.

**진입 경로**
로그인 (계정 생성 후).

**권한**

| 구분 | 내용 |
|---|---|
| 볼 수 있는 것 | 자신이 등록한 지인·그룹·모임, 배우자(ROLE-01)가 확정한 모임을 포함한 통합 일정 조망, 양가 공동 모임 |
| 만들 수 있는 것 | 지인 등록, 그룹 편성, 모임 생성(1:1 포함), 날짜 후보 제안, 배우자와 함께 참여하는 공동 모임 생성 |
| 수정·삭제할 수 있는 것 | 자신이 등록한 지인·모임 정보, 자신이 만든 모임의 날짜 후보 수정, 회신 마감 기한 연장 |
| 할 수 없는 것 | 배우자(ROLE-01)가 등록한 지인 정보를 직접 수정·삭제 (RISK-04), 초대받은 지인(ROLE-03)의 회신을 대신 확정 처리 |

**주요 시나리오**
`FLW-01`(지인 등록), `FLW-02`(모임 편성·일정 조율), `FLW-04`(전체 일정 조망) 참조.

## ROLE-03 초대받은 지인

**목표**
자신에게 온 청첩장모임 요청(여러 커플로부터 온 것을 포함)을 한 곳에서 파악하고, 참석 가능 여부를 회신하는 것.

**진입 경로**
인증 없는 초대 링크 (계정 생성 없음).

**권한**

| 구분 | 내용 |
|---|---|
| 볼 수 있는 것 | 자신이 초대된 모임의 날짜 후보·회신 마감·현재 진행 상태, 자신에게 온 모든 모임 요청 목록(동일 식별자로 묶인 경우) |
| 만들 수 있는 것 | 회신(가능/불가능) 등록 |
| 수정할 수 있는 것 | 마감 전까지 자신의 회신 변경 |
| 할 수 없는 것 | 모임 구성 변경, 다른 초대자의 회신 열람(`TBD:` 그룹 내 회신 현황 공개 여부는 정책 확인 필요), 지인 풀·타인 정보 접근 |

**주요 시나리오**
`FLW-03`(초대받은 지인의 회신) 참조.

## 역할 간 관계

### RISK-04 공동 소유 — ROLE-01 · ROLE-02

- 신랑·신부는 각자 자신이 등록한 지인 풀을 소유한다. 상대가 등록한 지인 정보를 직접 수정·삭제할 수 없다.
- 확정된 모임은 소유자와 무관하게 양쪽 모두에게 노출된다 (`REQ-10` 통합 조망). 목록에서 "누구 쪽 모임인지" 구분 표시가 필요하다 (`SCR-` 목록 화면에 반영, `policy.md` 참고).
- 상견례처럼 양가가 함께 나가는 모임은 한쪽이 생성하되 양쪽 모두를 구성원으로 등록할 수 있어야 한다 (`ENT-` 모임-지인 관계는 신랑측/신부측을 가리지 않는 다대다 구조여야 함).
- 동시 편집 충돌(같은 모임을 신랑·신부가 동시에 수정)은 발생 빈도가 낮다고 판단해 이번 범위에서는 마지막 저장 우선(단순 덮어쓰기)으로 처리하고, 별도 잠금 UI는 만들지 않는다. → `policy.md`에 명시.

### RISK-10 미인증 진입 — ROLE-03

- 초대받은 지인은 로그인 사용자(ROLE-01/02)와 완전히 다른 화면 세트를 쓴다. 지인 풀·모임 편성 화면에는 접근할 수 없고, 회신 전용 화면만 접근한다.
- 여러 커플로부터 동시에 요청을 받는 상황(원본 §2 유저스토리2)을 지원하려면, 초대받은 지인을 프로젝트(커플) 경계를 넘어 식별할 수 있어야 한다 — 이번 범위에서는 **연락처(전화번호)를 전역 식별자**로 가정하고 설계한다 (`ia.yaml` ENT 참고). 실제 인증 없이 전화번호만으로 식별하는 것이 안전한지는 `TBD:`로 남겨 `_handoff.md`에 기록한다.
- 초대 링크가 유출되면 제3자가 회신을 대신 남길 수 있다는 위험이 있다. 이번 범위에서는 링크 소지 = 본인으로 간주하는 낮은 신뢰 수준을 기본값으로 하되, 향후 추가 확인(이름 뒷자리 등)을 넣을 수 있도록 정책에 여지를 남긴다. → `policy.md` 참고.
