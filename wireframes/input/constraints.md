## 7. 화면별 설계 주의점 (상위기획 인계)

| 화면 | 주의점 |
|---|---|
| SCR-05 | 일반 모임 생성과 "긴급 모임"(RISK-05 우회) 두 흐름이 한 화면에 공존한다. 두 흐름을 시각적으로 명확히 분리해야 사용자가 실수로 회신 취합을 건너뛰지 않는다 |
| SCR-06 | 상태(회신중/확정대기/확정/완료/취소)별로 보여줄 정보와 가능한 행동이 크게 다르다. 사실상 5개 화면 변형을 하나의 SCR로 묶은 것이므로 설계 난이도가 가장 높다 |
| SCR-07 | 겹침 표시(RISK-03)와 신부측/신랑측/공동 구분을 동시에, 그것도 달력이라는 제한된 공간에서 표현해야 한다 |
| SCR-08, SCR-09 | ROLE-03 전용 트리다. 로그인 사용자 화면의 컴포넌트를 그대로 재사용하지 않는다. 여러 커플의 요청을 한 화면에 모으는 로직은 전화번호 전역 식별(POL-15, 미결)에 의존하므로, 이 정책이 바뀌면 화면 구조도 바뀐다 |
| SCR-02 | 100명 규모에서는 검색·그룹 필터가 있어야 실사용이 가능하다(RISK-06). 목록/필터 UI를 옵션이 아니라 필수 기능으로 설계한다 |
| SCR-10 | 배우자 연결(REQ-13)이 안 되면 통합 조망(SCR-07)이 의미가 없다. 온보딩 흐름에서 이 단계를 건너뛰지 않도록 유도가 필요하다 |
