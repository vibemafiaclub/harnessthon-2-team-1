# User Flow — 청첩장모임 스케줄러

> `wireframe` 스킬 입력 문서 2/4. flows.yaml의 상태 전이(ST-01~05)와 유저 플로우(FLW-01~07)를 정리했다. 화면 ID(SCR)는 ia.md, 정책 ID(POL)는 constraints.md를 참고한다.

## 1. 핵심 경로 (와이어프레임의 중심 흐름)

스킬 1단계에서 고를 핵심 경로의 후보다. 예비부부 쪽 경로를 기본으로 두고, 초대받은 지인 쪽 경로를 짝으로 붙인다. 둘은 같은 모임 레코드를 양쪽에서 다루므로 한 세트로 봐야 한다.

### 경로 A. 예비부부 (ROLE-01 / ROLE-02)

| 단계 | 화면 | 내용 |
|---|---|---|
| 진입 | SCR-01 홈 | 조치가 필요한 모임과 이번 주 남은 모임을 보고 "모임 편성"으로 이동 |
| 입력 | SCR-05 모임 편성 | 지인 선택(그룹 필터), 날짜 후보 2~3개, 회신 마감 입력 |
| 처리 | SCR-06 모임 상세 | 구성원별 회신이 모이는 것을 확인. 마감 도달 시 확정 대기로 전환 |
| 결과 | SCR-06 모임 상세 | 후보 중 최종 날짜 확정. 겹침 경고가 있으면 재확인 후 확정 |
| 다음 행동 | SCR-07 전체 일정 조망 | 배우자 모임과 합쳐 달력에서 확인, 겹침 여부 점검 |

### 경로 B. 초대받은 지인 (ROLE-03)

| 단계 | 화면 | 내용 |
|---|---|---|
| 진입 | SCR-08 내 초대 목록 | 문자·카카오로 받은 링크로 진입. 여러 커플의 요청이 한 목록에 보임 |
| 입력 | SCR-09 회신 입력 | 날짜 후보별 가능/불가능 표시 |
| 처리 | SCR-09 회신 입력 | 회신 제출 |
| 결과 | SCR-08 내 초대 목록 | 해당 요청이 "회신 완료"로 바뀜 |
| 다음 행동 | SCR-08 내 초대 목록 | 남은 미회신 요청으로 이동, 또는 확정된 날짜 확인 |

## 2. 모임 상태 전이 (ENT-03 모임)

### 상태

| ID | 상태 | 설명 | 종료 상태 |
|---|---|---|---|
| ST-01 | 회신중 | 모임이 생성되고 날짜 후보에 대한 참가자 회신을 받는 중. 생성 시 진입하는 시작 상태 | 아니오 |
| ST-02 | 확정대기 | 회신 마감 기한에 도달해 최종 날짜 확정을 기다리는 중 | 아니오 |
| ST-03 | 확정됨 | 최종 날짜가 정해져 구성원 전원에게 공유된 상태 | 아니오 |
| ST-04 | 완료 | 확정된 모임 날짜가 지나 이력으로 전환된 상태 | 예 |
| ST-05 | 취소됨 | 확정 여부와 무관하게 모임이 무산된 상태 | 예 |

### 전이

| From | To | 트리거 | 유형 | 주체 | 화면 | 알림 대상 | 비고 |
|---|---|---|---|---|---|---|---|
| ST-01 | ST-02 | 회신 마감 기한 도달 | 시간 | 시스템(작성자가 확인) | SCR-06 | ROLE-01, ROLE-02 | RISK-02. 마감 전 리마인더 POL-17, 마감 후 처리 POL-02 |
| ST-01 | ST-03 | 긴급 모임: 후보 제안·회신 취합을 생략하고 바로 확정 | 사용자 | ROLE-01/02 | SCR-05 | 배우자, 참가 지인 전체 | RISK-05 우회 경로. POL-05 |
| ST-02 | ST-03 | 작성자가 후보 중 최종 날짜 확정 | 사용자 | ROLE-01/02 | SCR-06 | 배우자, 참가 지인 전체 | REQ-09, POL-18. 배우자 대신 확정은 POL-01 |
| ST-02 | ST-05 | 확정 가능한 날짜가 없어 취소 | 사용자 | ROLE-01/02 | SCR-06 | 배우자 | POL-04 |
| ST-03 | ST-04 | 확정된 모임 날짜가 지남 | 시간 | 시스템 | SCR-04 | 없음 | RISK-12. POL-12. 목록 "완료" 탭으로 이동 |
| ST-03 | ST-05 | 확정된 모임을 취소 | 사용자 | ROLE-01/02 | SCR-06 | 배우자, 참가 지인 전체 | RISK-09. POL-04, POL-19. 재조율은 새 모임으로 생성하며 되돌리지 않는다 |

검토 포인트:
- 시간 기반 전이: ST-01→ST-02, ST-03→ST-04 (사용자 행동 없이 바뀌므로 화면이 그 사실을 알려야 한다)
- 되돌리기: ST-02→ST-05, ST-03→ST-05 (취소만 있고 "확정 취소 후 다시 회신중"은 없다)
- 우회: ST-01→ST-03 (긴급 모임)

## 3. 유저 플로우

### FLW-01 지인 등록과 그룹 편성 — ROLE-01/02

트리거: 청첩장을 줄 지인을 서비스에 처음 등록하려 할 때

| 순서 | 화면 | 행동 | 결과 |
|---|---|---|---|
| 1 | SCR-02 | 지인 목록에서 "지인 추가" 선택 | SCR-02.1 진입 |
| 2 | SCR-02.1 | 이름·연락처 입력, 소속 그룹을 복수 선택(기존 그룹 선택 또는 새 그룹 즉시 생성) | 지인 레코드 생성, 그룹과 N:M 연결 |
| 3 | SCR-02 | 등록된 지인이 목록과 그룹 필터에 반영된 것을 확인 | |

결과: 지인이 하나 이상의 그룹에 등록되어 모임 편성(FLW-02)에서 선택 가능해진다.

예외:
- 이미 등록된 연락처로 다시 등록 시도 → SCR-02.1에서 중복 후보를 안내하고 기존 레코드에 그룹만 추가할지 확인 (POL-06)
- 그룹을 지정하지 않고 저장 → 허용하되 목록에서 "미분류" 필터로 노출 (POL-07)

### FLW-02 모임 편성과 일정 조율 — ROLE-01/02

트리거: 특정 그룹 또는 개별 지인과 청첩장모임을 잡고 싶을 때

| 순서 | 화면 | 행동 | 결과 |
|---|---|---|---|
| 1 | SCR-05 | 지인 선택(그룹 필터 활용), 날짜 후보 다건 입력, 회신 마감 기한 설정 | 모임 생성, ST-01 진입 |
| 2 | SCR-06 | 참가자별 회신 현황과 겹침 경고 확인 | |
| 3 | SCR-06 | 회신 마감 도달 후 후보 중 최종 날짜 확정 | ST-02 → ST-03 |
| 4 | SCR-06 | 확정 결과가 구성원 전원에게 공유되는지 확인 | |

결과: 모임이 확정되어 전체 일정 조망(SCR-07)에 반영된다.

예외:
- 마감까지 일부 인원이 미회신 → SCR-06에서 마감 연장 또는 미응답자 제외 후 확정 진행 (RISK-02, RISK-08, POL-02)
- 확정하려는 날짜에 이미 다른 모임이 있음 → SCR-06에서 겹침 경고를 표시하되 확정을 차단하지 않고 재확인만 요구 (RISK-03, POL-03)

### FLW-03 배우자 계정 연결 — ROLE-02

트리거: 회원가입 직후, 또는 배우자가 먼저 만든 초대 코드를 받았을 때

| 순서 | 화면 | 행동 | 결과 |
|---|---|---|---|
| 1 | SCR-10 | 배우자 초대 코드를 생성하거나, 배우자가 보낸 코드를 입력 | |
| 2 | SCR-10 | 연결 성공 확인 | 계정이 커플에 연결됨 |

결과: 신랑·신부 계정이 하나의 커플로 묶여 서로의 확정 일정을 공유해 볼 수 있다 (REQ-13).

예외:
- 잘못된 초대 코드 입력 → 오류 표시 후 재입력 요청 (POL-08)
- 이미 다른 계정과 연결된 코드 → 커플은 정확히 2개 계정만 허용하므로 연결을 거부하고 사유 안내 (POL-08)

### FLW-04 전체 일정 조망에서 겹침 확인 — ROLE-02

트리거: 이번 달 남은 모임을 배우자 것까지 합쳐 확인하고 싶을 때

| 순서 | 화면 | 행동 | 결과 |
|---|---|---|---|
| 1 | SCR-01 | 홈에서 "전체 일정 조망"으로 이동 | |
| 2 | SCR-07 | 월별 확정 모임을 신부측·신랑측·공동 구분과 함께 확인 | |
| 3 | SCR-07 | 같은 날짜에 겹치는 모임이 강조 표시된 것을 확인하고 탭해 상세로 이동 | SCR-06 진입 |

결과: 결혼식 전까지 남은 모든 확정 모임과 겹치는 날짜를 파악한다 (REQ-10, REQ-11).

예외:
- 아직 확정된 모임이 하나도 없음 → 빈 상태로 안내하고 모임 편성(SCR-05)으로 유도 (RISK-07)

### FLW-05 초대받은 지인의 회신 — ROLE-03

트리거: 청첩장모임 초대 링크를 문자·카카오 등으로 받았을 때

| 순서 | 화면 | 행동 | 결과 |
|---|---|---|---|
| 1 | SCR-08 | 초대 링크로 진입해 자신에게 온 모임 요청 목록 확인(여러 커플의 요청 포함) | |
| 2 | SCR-09 | 응답할 모임을 선택해 날짜 후보별 가능/불가능 표시 | 회신 레코드 생성 |
| 3 | SCR-09 | 회신 제출 | |

결과: 회신이 모임 작성자에게 반영되어 SCR-06 회신 현황에 나타난다 (REQ-06, REQ-14, REQ-15).

예외:
- 회신 마감 기한이 지난 뒤 접속 → SCR-09에서 마감 지남을 안내하고 입력을 막되, 이미 확정된 날짜가 있으면 결과를 보여줌 (RISK-02, POL-09)
- 마감 전 회신을 바꾸고 싶음 → SCR-09에서 기존 회신을 다시 열어 수정 허용 (POL-09)

### FLW-06 긴급 모임 우회 확정 — ROLE-01/02

트리거: 결혼식이 임박해 정식 회신 절차를 밟을 시간이 없을 때

| 순서 | 화면 | 행동 | 결과 |
|---|---|---|---|
| 1 | SCR-05 | "긴급 모임" 옵션으로 후보 제안 없이 참가자와 확정 날짜를 바로 입력 | 모임이 ST-03으로 바로 생성 |
| 2 | SCR-06 | 구성원에게 확정 사실이 공유되는지 확인 | |

결과: 정규 절차(회신 취합) 없이도 확정된 모임이 즉시 전체 일정에 반영된다 (RISK-05, POL-05).

예외:
- 구성원 중 일부가 이미 다른 확정 모임과 겹침 → SCR-06에서 겹침 경고를 표시하되 생성 자체는 막지 않음 (RISK-03, POL-03)

### FLW-07 확정된 모임 취소·재조율 — ROLE-01/02

트리거: 확정된 모임을 부득이하게 취소해야 할 때

| 순서 | 화면 | 행동 | 결과 |
|---|---|---|---|
| 1 | SCR-06 | 확정된 모임에서 "취소" 선택, 취소 사유 입력(선택) | ST-03 → ST-05 |
| 2 | SCR-06 | 취소 사실이 배우자와 참가 지인에게 공유되는지 확인 | |
| 3 | SCR-05 | 필요 시 같은 구성원으로 새 모임을 다시 편성 | 새 모임이 ST-01로 생성 |

결과: 취소된 모임은 완료 이력과 구분되어 남고(RISK-12, POL-12), 필요하면 새 모임으로 재조율된다 (RISK-09).

예외:
- 참가자 다수가 이미 일정을 비워둔 상태에서 취소 → 강제 규정은 두지 않되, 취소 알림에 사유를 포함해 신뢰 저하를 최소화 (POL-04, POL-19)

## 4. 역할별 플로우 매핑

| 역할 | 주요 플로우 |
|---|---|
| ROLE-01 예비신부 | FLW-01, FLW-02, FLW-04, FLW-06, FLW-07 |
| ROLE-02 예비신랑 | FLW-01, FLW-02, FLW-03, FLW-04, FLW-06, FLW-07 |
| ROLE-03 초대받은 지인 | FLW-05 |

FLW-03과 FLW-04의 주체가 ROLE-02로 적혀 있지만 ROLE-01도 동일하게 수행한다. 권한이 대칭이기 때문이다.
